## 0 TL;DR

VLM은 high-level decision을, E2E는 그것에 따른 precise한 waypoint 생성을 담당하자.

## 1 배경

### 1.1 연구 배경

E2E 자율주행은 강력한 planning 역량을 보여주나 commonsense의 부족으로 복잡하고 드문 시나리오에서 고군분투하며 해석가능성이 부족하다. VLM은 장면 이해와 추론에 탁월하나 정확한 수학적 예측에 한계가 있다.

#### 문제 1

자율주행에 LVLM(Large Vision-Language Model)을 응용하는 방식으로 두 가지가 있다.

- LVLM을 planner로 직접 사용하여 trajectory를 생성
    - 한계: VLM 특성 상 정확한 trajectory 계산 어려움

- LVLM을 E2E 모델과 결합하여 정확한 trajectory는 E2E가 생성
    - 한계: 관련된 선행 연구는 그럼에도 불구하고 여전히 LVLM이 러프한 low-frequency trajectory까지는 생성하도록 했기 때문에 여전히 VLM의 본질적인 문제가 존재한다 **(문제 1)**.

#### 문제 2

현재 많이 사용되는 LVLM들은 multi-image input에 최적화되어 있지 않다. Driving task를 위한 기존 LVLM들은 front-view 단일 이미지만 입력받거나 혹은 multi-image를 받더라도 상세한 설계나 효과에 대한 검증이 부족하다.

#### 문제 3

주행 태스크를 위한 LVLM의 효과적인 학습을 위해서는 적합한 데이터와 전략이 요구되나 기존에는 그러지 못했다. 학습 데이터 관점에서, 기존 연구들의 학습 데이터들은 planning task를 위한 설계가 아니라 detection과 같은 다른 태스크를 위한 설계였다. 학습 전략 관점에서, 기존 연구들은 general-purpose의 pre-training을 하고 driving을 위한 fine-tuning하는 방식을 채택했으나 저자들의 실험 결과를 보았을 때 이것은 최적의 선택이 아닐 수 있다.

### 1.2 핵심 아이디어

#### 주장 1
**(문제 1)**을 해결하기 위해, VLM은 high-level planning(e.g. 'ACCELERATE, TURN_LEFT')을 수행하고 E2E는 low-level trajectory를 계산하도록 한다. 이를 통해 VLM은 정밀한 숫자 예측을 피하고 사전학습된 상식을 결정에 활용하는 이점을 얻으며, E2E는 학습 난이도가 줄어 궤적이 더 정확해지는 이점을 얻는다.

#### 주장 2
**(문제 2)**를 해결하기 위해, image token을 인코딩하고 압축하는 Driving Vision Adapter를 제안한다. 그리고 surround-view scenario를 위해 디자인된 프롬프트를 도입한다. 이를 통해 모델 붕괴 없이 surround-view 다중 이미지를 적은 연산량과 적은 메모리 사용량으로 처리하며 시점 간 공간 이해를 바탕으로 더 정확한 high-level 결정을 얻는다.

#### 주장 3
**(문제 3)**을 해결하기 위해, 학습 데이터 관점에서는 planning과 관련된 단서들에 대한 VLM의 이해를 강화하기 위해 디자인된 planning-oriented QA 시리즈를 도입하고 그 효과를 검증한다. 학습 전략 관점에서는 3-stage 학습 전략을 제안한다. 뿐만 아니라 오토 라벨링으로 데이터를 대규모로 생성하도록 한다. 이를 통해 general purpose pre-training을 먼저 하고 그 다음에 주행 관련 fine-tuning하는 방식 대비 더 좋은 성능을 얻는다.

## 2 조건

### 2.1 모델
(모델 아키텍처는 본문 그림 참조)

#### Senna-VLM

- Input
    - multi-view image sequence
    - navigation command (e.g., 'go straight')
    - user instruction (e.g., 'Plan the meta-action for driving safely.')

- Do
    - encoding
        - encode image into tokens via ViT and Driving Vision Adapter
        - encode text(User Instruction and multi-view prompts) into tokens
        - concatenate image tokens and text tokens.
    - process VLM
    - process Meta-action Encoder

- Output
    - high-level decision (e.g., 'DECELERATE, STRAIGHT.') which directly is fed into planning module of Senna-E2E.

#### Senna-E2E

Extended from VADv2.

- Input
    - multi-view image sequence
    - navigation command

- Do
    - perception module
        - detect dynamic objects.
        - generate a local map.
    - motion prediction module
        - predict the future trajectory of dynamic objects.
    - planning module
        - generate trajectory with meta-action features from Senna-VLM as well as scene information from the input.

- Output
    - trajectory

#### Driving Scene Understanding

The steps of Planning-oriented QA and the corresponding examples are as follows:

- Scene Description
    - Q: 이 장면에서 주행 계획을 세우기 위한 핵심 요소를 설명해라.
    - A: 낮의 도심 교차로이다. 차들이 신호대기 중이다. 횡단보도를 건너는 사람이 보인다. ...
- Traffic Signal Detection 
    - Q: 주행 계획에 영향을 주는 신호등이 있다면 무슨색이니? Red/Green/Yellow/None으로 대답해라.
    - A: Red
- Vulnerable Road User Identification
    - Q: 20m 이내 교통약자가 있니?
    - A: 보행자가 12m 전방 3m 좌측에 있다.
- Motion Intention Prediction
    - Q: (정답 3D 박스로부터 얻은 각 dynamic object의 종류, 위치, 속도를 자연어로 주며) 이 오브젝트들의 미래 주행 행동을 예측해라.
    - A: Object 1: KEEP, LEFT_TURN. Object 2: STOP, STRAIGHT.
- Meta-action Planning
    - Q: 너의 현재 속도는 x m/s이다. navigation command는 'go straight'이다. 주행 장면을 고려했을 때 다음 3초간의 너의 계획은 무엇이니?
    - A: DECELERATE, STRAIGHT.
- Planning Explanation
    - Q: 너의 현재 속도는 x m/s이다. navigation command는 'go straight'이다. 너의 미래 3초간 행동은 DECELERATE, STRAIGHT이다. 그 이유를 대라.
    - A: 나는 교차로에 접근하고 있고 신호등은 빨간불이다. 그래서 나는 멈춰야 하고, 신호등이 초록불이 될 때까지 기다려야 한다.

QA above is only for train time. Senna doesn't answer these questions and directly output meta-action planning in inference time. For more information, see Fig. 7.

#### Training Strategy

3-stage training for Senna-VLM

1. Mix Pre-training
- training the Driving Vision Adapter using single-image data with the VLM frozen.
- 'mix'의 의미는 데이터의 소스가 LLaVA로부터 온 것도 있고 자체적으로 제안하는 driving scene description data도 있다는 의미라고 함.

2. Driving Fine-tuning
- fine-tuning Senna-VLM with planning-oriented QA.

3. Planning Fine-tuning
- fine-tuning Senna-VLM with meta-action QA.

### 2.2 실험 설정

#### Dataset

별도로 명시되지 않으면 Senna는 DriveX의 training set으로 학습되고 validation set으로 metrics를 보고한다.

- nuScenes
    - 1,000 driving scenes, each lasts for about 20 seconds.
- DriveX
    - 1,000K driving clips, each lasts for 3 seconds.
    - randomly sampled 800k clips for the training set and 200k for the validation set.

#### Metrics
- accuracy and F1 Score (for the high-level decision)
- BLEU-4, CIDEr, METEOR (for the driving scene descriptions)

## 4 결론 및 한계

### 4.1 결론

- VLM과 E2E 모델을 결합해, 고수준 결정에서 저수준 궤적까지 이어지는 구조화된 계획을 하는 Senna를 제안했다.
- 실험이 Senna의 우수한 성능, 교차 시나리오 일반화와 전이 능력을 보여준다.
- 언어 기반 계획으로 VLM과 E2E를 결합하는 방식의 가능성을 보여준다.
- 앞으로는 미리 정해진 meta-action이 아닌, 더 세밀하고 자유로운 언어 지시로 궤적을 제어하는 방향을 연구하겠다.

### 4.2 한계

- VLM 특성 상 latency 문제는 여전하다.
- 데이터가 더 많아지면 모델의 개선 여지가 있다.

### 5.1 주장의 타당성

#### 주장 1

TABLE 2에서 Senna가 타 E2E 대비 더 낮은 L2 distance를 보인 것을 통해, E2E의 precise한 numerical computation이라는 강점이 VLM-E2E에 잘 inherited 되었다고 해석할 수 있다.

TABLE 2에서 Senna와 DriveVLM의 성능을 비교하여 이 논문에서 주장하는 'VLM과 E2E의 역할 decoupling'의 타당성을 확인할 수 있다. 반면 *가 달린 모델들의 숫자들은 ego state를 input한 결과로, nuScenes의 잠재적인 ego state 문제를 포함하고 있다는 점에 주의해야 한다. ego state를 넣지 않은 결과에서는 DriveVLM 모델은 빼놓고 보고했다는 점에서 'Senna vs DriveVLM'의 직접적인 비교가 어렵다는 점이 한계점으로 보인다.

TABLE 3의 DriveVLM은 DriveVLM의 단계적 학습 방식(CoT)을 따른 것인지 아니면 저자들의 방식으로 학습했는지에 대한 언급이 없기 때문에, DriveVLM 논문의 저자들의 설계에서 벗어난 학습을 했다면 DriveVLM의 숫자가 비관적으로 나온 것일 가능성이 있다.

TABLE 3에서 Senna의 L2 성능이 VADv2(G.T. Meta-action input)보다 더 낮은 이유로는 VLM의 Meta-action 출력이 틀린 경우가 포함되어 있기 때문이라고 바라볼 수 있다.

#### 주장 2

논문에서 제안하는 시점 프롬프트가 효과적인지는 알 수 없다. 만약에 ablation study로 시점 프롬프트를 넣었을 때랑 넣지 않았을 때 성능이 어떻게 달라지는지 보였다면 그것이 효과적인지 효과적이지 않은지 확인할 수 있었지만 위의 성능 개선이 6 camera에서 온 것인지 아니면 시점 프롬프트에서 온 것인지 분리할 수 없다.

#### 주장 3

TABLE 4에서 횡방향보다 종방향으로 큰 성능 향상을 보이는 것이, QA를 통해 조향보다 가/감속에서 이점을 보이고 있는 것인지, 아니면 데이터셋 특성 등 다른 영향에 의한 것인지는 이것을 통해서는 알 수 없다.

TABLE 9는 이러한 경험적인 결과를 숫자로 보여주고 있으나, 이에 대한 원인을 저자들도 정확하게 설명하고 있지 않는 것으로 보인다.

TABLE 7에서 데이터가 많을수록 모델의 성능이 좋아지는 것은, 오토라벨링이 필수적이라는 것을 보여준다.

#### 종합

QA와 다중 이미지 인코딩은 결정 지표로만 평가되어, 그것이 최종 궤적 개선까지 이어지는지는 확인되지 않았다. 즉, 역할 분담 재정의는 통제된 비교로 뒷받침되지만, QA와 인코딩 설계의 효과는 결정 수준에서만 검증되었다.

#### 그 외

DriveX로 사전학습된 weight를 가지고 nuScenes에 fine-tuning하니까 성능이 더 좋아졌다는 것을 보이고 있는데, 이 서술이 왜 필요한지 이해가 되지 않았다. 왜냐하면 이것은 DriveX 데이터셋의 효용성을 주장하고 있는 것으로 보이지 않으며, 모델의 우수성을 주장하기에도 무리가 있는 것이 만약에 성능 향상의 원인이 많은 데이터를 학습시킴으로써 온 것이 지배적이라면 그것은 모델의 우수성과는 별개의 이야기이기 때문이다.

### 5.2 한계

- DriveX의 validation dataset으로 metrics를 보고하였는데, 이 val set이 hyperparameter를 조정하는데 사용되었는지 논문 상에서 확인할 수 없었다.

### 5.3 느낀점

이 논문은 자율주행에 VLM이 도입되는 초기 시기(2024년)에 나온 논문으로, 현재 시점(2026년)에서 자율주행 VLM 모델을 상상했을 때 정석적인 구조를 가지고 있는 모델 중 하나인 것 같다. 그정도로 frontier model이라고 생각한다.

VLM이 planning-oriented QA의 방식으로 설명하게 한 것이 처음 제대로 접해 본 입장에서 새로웠고 이를 통해서 모델이 뉴런과 시냅스를 타고 어떤 결론에 도달하는 것에 가이드라인 또는 요령을 내재적으로 체화한 것이 아닌가 하는 느낌을 받았다.

### 5.4 내 연구와의 관계

VLM의 상위 결정, E2E가 그 결정을 가지고 하위 결정을 하는 것, E2E는 뿐만 아니라 영상 정보도 가지고 low-level 주행 결정을 한다는 점에서 나의 연구의 기본이 되는 아이디어이다. 나는 여기에 더 나아가서 VLM이 잘못된 상위 결정을 했을 때에 관심을 가지며 E2E는 DiT를 사용하도록 설정했다.
